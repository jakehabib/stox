Design research · lens: moments & motion

The drama is already in the data

Four proposals, rendered against the app's real palette. Nothing here removes an avatar, a logo, a colour or a row. Every number below is derived from something the database already stores — the box score's drives[] array, the final scores, the clinch math, the recap text. It is all currently computed and then thrown away at the render boundary.

01 The Week Report Replaces the 7-second toast · Tier 1 · fires on every Advance

Today, pressing Advance ▸ returns the string "Week 8 complete: 16 games played." in a 320 px card that disappears after seven seconds. Your own score is not in it. This is what that moment could be instead: your result at broadcast scale, what it changed, one game ball, the room, and what's next. Dismissible with Escape, a click outside, or any navigation — never a mandatory click.

02 Game Shape From boxScore.drives[] · already persisted · never read

Every played game stores 22 drives in chronological order with points per drive. The score differential across those drives is a silhouette you read in 200 milliseconds — the same device ESPN's win-probability graph has used since 2016, where the Game Excitement Index is literally the length of that jagged line pulled straight. 03 Result weight Half a day of work · zero new data · zero extra pixels

The current schedule renders a 28-point humiliation and an 8-point road win over the same team in identical type at identical weight. The margin is already sitting in the row. Right-hand column: the loser's number drops to muted on a blowout, a one-score game gets an accent rule under the score, a season's shape reads down the column as good and bad weeks rather than a list of digits. Nothing is removed and no row gets shorter.

04 The Trophy Moment Tier 0 · the only full-screen interruption in the game · ≤1 per season

Winning the championship currently returns the string 'The championship game is complete! Welcome to the offseason.' — in the same 320 px card, in the same corner, for the same seven seconds, in the same typeface as "Week 3 complete". That is the whole payoff of a season. This is the one thing in this document I would stop the game for, and the reason the budget everywhere else is so strict: Crusader Kings III is the cautionary tale, where the top community mod is literally called Less Event Spam.

— What I would not interrupt for

A game that celebrates everything celebrates nothing. The rule I would hold every one of these to: if it fires on more than one Advance in three, it may not interrupt — it must earn its place inside something the player was already going to read. Explicitly, no full-screen moment for:

  • Any regular-season win or loss, including a blowout, an upset or a last-second finish. These get weight, not a modal.
  • Clinching a playoff spot or the division — you can clinch a spot, then the division, then a bye, which would be three interruptions in four weeks.
  • Any milestone: 1,000 yards, 4,000 yards, a franchise record. lib/storyline.ts already found these cluster and capped itself at four for exactly this reason.
  • Any signing, trade, cut or draft pick — you initiated it, you already know. Celebrating an action the player just took is the slot-machine failure.
  • Injuries. Sixteen a week league-wide; lib/wireRank.ts already collapses them correctly.
  • A rookie's first start or a development jump — these belong on the player's row, where they persist, not in a popup that fires once and is gone.
  • Advancing multiple weeks at once. One report at the end of the whole span, never one per iteration. A player who asked to skip to the playoffs has explicitly asked not to be stopped.
